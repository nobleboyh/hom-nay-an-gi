# Decision Log — Hôm Nay Ăn Gì PRD

## Decisions

| # | Decision | Rationale | Date |
|---|----------|-----------|------|
| 1 | MVP prioritizes existing ingredients first; shopping list secondary | Keep scope lean, solve the core "what can I cook" problem first | 2026-05-31 |
| 2 | No external integrations (e-receipt, smart fridge, delivery APIs) for MVP | Cost and complexity too high for initial build | 2026-05-31 |
| 3 | No swipe-based (Tinder) discovery | Users need overview, not serial one-at-a-time browsing | 2026-05-31 |
| 4 | Tags filter on dish level, not ingredient level | More intuitive — users think about dish type, not ingredient categories | 2026-05-31 |
| 5 | Bilingual (Vietnamese + English) | Core market is Vietnamese but app should be accessible to wider audience | 2026-05-31 |
| 6 | Guest mode with local storage; cloud sync on login | Minimizes friction to try the app; data persistence for returning users | 2026-05-31 |
| 7 | Cross-platform (iOS + Android), tech stack TBD | Maximize reach; team decides on Flutter vs RN vs other | 2026-05-31 |
| 8 | Hybrid dish data: API + web scraping + UGC (UGC deferred to v2) | Balance between breadth of content (API/scraping) and depth (UGC later) | 2026-05-31 |
| 9 | External links only to delivery partners — no in-app ordering | Avoids payment processing, delivery logistics complexity | 2026-05-31 |
| 10 | Basic offline support — cache recent results | Usable without connectivity for previously viewed dishes | 2026-05-31 |
