# Decision Log — Hôm Nay Ăn Gì UX (v4 — Open Design)

## Decisions

| # | Decision | Rationale | Date |
|---|----------|-----------|------|
| 1 | OKLCH color space | Perceptually uniform, modern, works across display technologies. Better than hex for maintainability. | 2026-06-01 |
| 2 | Söhne / Avenir Next for display | Warm, editorial feel that matches Vietnamese food-market aesthetic. Alternatives: Fraunces (v3), platform-native (v1). | 2026-06-01 |
| 3 | System fonts for body | SF Pro Text / system-ui ensures native readability, dynamic type support, no web font overhead. | 2026-06-01 |
| 4 | 4 bottom tabs (Home, Discover, Favorites, Profile) | Profile replaces Settings-as-drawer from v1. Keeps all core surfaces one tap away. Login is the first surface on Profile tab. | 2026-06-01 |
| 5 | Unified input + filters on Home | v2 separated Surprise Me hero from ingredient input. v4 combines input + filters on one scrollable surface for faster flow. | 2026-06-01 |
| 6 | Shopping list as full page (not bottom sheet) | v1 used a bottom sheet; v4 promotes it to a full page with checkable items, tip card, and save action. Richer interaction surface. | 2026-06-01 |
| 7 | Toast-based feedback throughout | Minimal interruption. All saves, copies, errors, and confirmations use toast. No modal dialogs for transient states. | 2026-06-01 |
| 8 | Vertical timeline (not horizontal bar chart) | v1/v2 used horizontal timeline; v3/v4 use vertical dot-and-bar. Better for reading step details on mobile, supports longer descriptions. | 2026-06-01 |
| 9 | Favorites with search + animated remove | Search within favorites for quick access. Remove animation (scale-down + fade) gives tactile feedback. | 2026-06-01 |
| 10 | Mood/craving tags in collapsible section | Progressive disclosure — food type and cuisine are always visible; mood tags are secondary, hidden by default, expandable on demand. | 2026-06-01 |
| 11 | Surprise Me as secondary button next to Search | v2 had separate Surprise Me hero. v4 puts it next to Search for equal prominence but secondary visual weight. | 2026-06-01 |
| 12 | Guest mode with benefit card on login screen | Encourages registration without blocking core features. Benefits card makes value proposition visible before login. | 2026-06-01 |
| 13 | Vietnamese-first copy | All UI text authored in Vietnamese. English is secondary/translation. Layout tuned for Vietnamese diacritic rendering. | 2026-06-01 |
| 14 | No skeleton loading states in prototype | v4 prototype skips loading states. Production should implement skeleton cards for Results and Discover. | 2026-06-01 |
| 15 | Global click delegation for interactions | Uses document-level event delegation for card expand, collapsible toggle, checkbox toggle, chip toggle. Simple, no framework needed. | 2026-06-01 |

## Open Questions

- **Login enforcement for bookmarks**: v4 does not enforce auth on bookmark. Should guest bookmark trigger login prompt? PRD says yes; v4 prototype behavior needs alignment.
- **Dark mode palette**: Not defined in v4. DESIGN.md frontmatter lists only light tokens. Full dark mode deferred.
- **Empty states differentiation**: Favorites empty state vs. search-no-results should be different messages. v4 uses same state for both.
- **Serving adjuster UX**: v4 uses −/+ buttons. Consider slider for finer control in production.
- **Discover → external link flow**: v4 navigates from Discover cards to Recipe. Production should show restaurant detail with external delivery link.
